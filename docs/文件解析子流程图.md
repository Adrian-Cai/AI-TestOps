 **文件解析子流程图**链路：

> 文件上传 → 文件接入 → Apache Tika 解析 → 文本与元数据提取 → 内容清洗 → 分段分块 → 结构化存储

两版：

1. **流程版**：适合放在总架构里
2. **细化版**：适合后续按步骤开发

---

# 一、文件解析子流程图（流程简洁版）


```mermaid
flowchart TD

    A[用户上传文件] --> B[文件接入层]
    B --> C[文件基础校验]
    C --> C1{文件是否合法}

    C1 -->|否| X[返回错误信息<br/>格式不支持 / 文件为空 / 文件过大]
    C1 -->|是| D[保存原始文件]

    D --> E[创建解析任务]
    E --> F[调用 Apache Tika]
    F --> G[提取文本内容]
    F --> H[提取元数据]

    G --> I[内容清洗]
    I --> I1[去除噪声字符]
    I --> I2[统一换行与空格]
    I --> I3[清理无效空白]
    I --> I4[合并正文内容]

    H --> J[标准化元数据]
    J --> J1[文件名]
    J --> J2[文件类型]
    J --> J3[作者]
    J --> J4[创建时间]
    J --> J5[页数/工作表信息]

    I --> K[文档结构化处理]
    J --> K

    K --> K1[按段落切分]
    K --> K2[按章节切分]
    K --> K3[按长度分块]
    K --> K4[生成统一 JSON 结构]

    K4 --> L[保存文档主表]
    K4 --> M[保存文档分块表]
    K4 --> N[保存解析结果 JSON]

    N --> O[返回解析完成结果]
```

# 二、文件解析子流程图（细化开发版）

适合你一步一步落地实现，因为它把“异常处理、任务状态、存储结果”拆得更清楚。

```mermaid
flowchart TD

    A[用户上传文件] --> B[接收文件请求]
    B --> C[识别文件类型]
    C --> D[校验文件大小]
    D --> E[生成 file_hash]
    E --> F{文件是否重复}

    F -->|是| F1[标记重复文件<br/>可直接复用已有解析结果]
    F -->|否| G[保存原始文件到对象存储或本地]

    F1 --> H[创建文档记录]
    G --> H

    H --> I[写入 document 主表]
    I --> J[创建解析任务]
    J --> K[更新 parse_status = PROCESSING]

    K --> L[调用 Apache Tika 解析]
    L --> M{解析是否成功}

    M -->|否| M1[记录错误日志]
    M1 --> M2[更新 parse_status = FAILED]
    M2 --> Z[返回解析失败结果]

    M -->|是| N[提取 raw_text]
    M --> O[提取 metadata]

    N --> P[文本清洗]
    P --> P1[去掉特殊噪声字符]
    P --> P2[统一编码格式]
    P --> P3[去除多余空白]
    P --> P4[按段落整理文本]

    O --> Q[元数据标准化]
    Q --> Q1[title]
    Q --> Q2[author]
    Q --> Q3[content_type]
    Q --> Q4[created_time]
    Q --> Q5[page_count / sheet_count]

    P4 --> R[结构化切分]
    Q --> R

    R --> R1[sections 切分]
    R --> R2[chunks 切分]
    R --> R3[计算 chunk_index]
    R --> R4[估算 token_count]

    R1 --> S[生成统一解析结果 JSON]
    R2 --> S
    R3 --> S
    R4 --> S

    S --> T[保存 document.raw_text]
    S --> U[保存 metadata_json]
    S --> V[批量保存 document_chunk]
    S --> W[保存完整 parse_result_json]

    T --> X[更新 parse_status = SUCCESS]
    U --> X
    V --> X
    W --> X

    X --> Y[返回解析结果摘要]
```

# 三、突出“支持多文件类型”，可以用这版

强调 Demo 的输入源范围：`md / txt / ppt / xls / pdf`。

```mermaid
flowchart TD

    A[上传文件] --> B{文件类型}

    B -->|md| C1[Markdown 文件]
    B -->|txt| C2[文本文件]
    B -->|ppt| C3[PPT 文件]
    B -->|xls| C4[Excel 文件]
    B -->|pdf| C5[PDF 文件]

    C1 --> D[统一进入文件接入层]
    C2 --> D
    C3 --> D
    C4 --> D
    C5 --> D

    D --> E[格式校验 / 大小校验 / hash 计算]
    E --> F[保存原始文件]
    F --> G[调用 Apache Tika]

    G --> H[提取正文文本]
    G --> I[提取元数据]
    G --> J[识别页码 / 工作表 / 标题等结构信息]

    H --> K[文本清洗]
    I --> L[元数据清洗]
    J --> M[结构信息整理]

    K --> N[文档标准化]
    L --> N
    M --> N

    N --> O[生成统一结构]
    O --> O1[document]
    O --> O2[metadata]
    O --> O3[sections]
    O --> O4[chunks]

    O1 --> P[存储 document 主表]
    O2 --> Q[存储 metadata JSON]
    O3 --> R[存储 sections 或解析结果表]
    O4 --> S[存储 chunk 表]

    S --> T[返回解析完成]
```

# 四、我建议你最终采用的“文件解析子流程图”

建议优先用 **第二版“细化开发版”**，因为它最接近真实实现。

## 开发步骤落地

### 第一步：文件接入

先做：

* 上传接口
* 文件格式校验
* 文件大小校验
* 文件 hash 计算
* 原始文件保存

### 第二步：文档记录

再做：

* `document` 主表入库
* 解析任务状态维护

### 第三步：Tika 解析

再做：

* 调用 Tika
* 提取 `raw_text`
* 提取 `metadata`

### 第四步：内容标准化

再做：

* 清洗文本
* 切分 section
* 切分 chunk

### 第五步：结果存储

最后做：

* `document`
* `document_chunk`
* `parse_result_json`
* 更新解析状态
