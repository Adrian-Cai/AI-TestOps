# AI TestOps 启动运行说明

本文档说明如何在本机启动当前 Spring Boot Demo，并访问前端页面、接口文档、文档解析、AI 需求抽取、测试用例生成评审和导出功能。

## 1. 当前为什么之前没有前端页面

最初只实现了后端 API、数据库表、Tika 解析和 Knife4j 接口文档，没有创建 `src/main/resources/static/index.html`，所以访问 `http://localhost:8080/` 时不会看到业务页面。

现在已补充一个零构建静态前端页面，由 Spring Boot 直接托管：

```text
src/main/resources/static/index.html
src/main/resources/static/styles.css
src/main/resources/static/app.js
```

启动后访问：

```text
http://localhost:8080/
```

接口文档访问：

```text
http://localhost:8080/doc.html
```

## 2. 环境要求

- JDK 17 或更高版本，项目编译目标为 Java 17。
- MariaDB 10.11.14。
- Windows 可直接使用项目内 `mvnw.cmd`，不要求本机提前安装 Maven。
- 浏览器使用 Chrome、Edge 或 Firefox 均可。

## 3. 数据库说明

当前项目连接你在 `.env` 中配置的远程 MariaDB。应用启动时不会自动执行建表 SQL，也不再把初始化 SQL 放在 `src/main/resources/sql` 下。

如果远程数据库已经创建并且表结构已存在，直接启动项目即可。测试环境仍使用 `src/test/resources/schema.sql` 初始化 H2 内存库，不影响远程数据库。

当前运行需要远程库至少具备以下表：

```text
ai_testops_document
ai_testops_document_chunk
ai_testops_document_parse_result
ai_testops_generation_record
ai_testops_prompt_template
ai_testops_requirement_extract
ai_testops_validation_result
ai_testops_test_case_draft
ai_testops_test_case
ai_testops_requirement_case_mapping
ai_testops_review_record
```

如果只是创建了数据库 schema 但还没有建表，服务启动或访问接口时会因为表不存在而失败。

## 4. 统一使用 .env 配置

数据库和大模型配置统一放在项目根目录 `.env`。不要把真实密码、API Key 提交到仓库。

`.env` 示例：

```properties
DB_URL=jdbc:mariadb://your-remote-host:3306/ai_testops?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
DB_USERNAME=your_db_user
DB_PASSWORD=your_db_password
SERVER_PORT=8080
AI_TESTOPS_UPLOAD_DIR=./data/uploads

# 本地无密钥联调可使用 MOCK
AI_PROVIDER=MOCK
AI_MODEL_CODE=default
AI_MODEL_NAME=mock-requirement-extractor

# 真实 OpenAI-compatible API 配置
AI_API_BASE=https://api.openai.com
AI_API_KEY=your_api_key
AI_TEMPERATURE=0.2
AI_MAX_TOKENS=4096
```

如果要调用真实 OpenAI-compatible API，将 `AI_PROVIDER` 改成非 `MOCK`，并配置：

```properties
AI_PROVIDER=OPENAI
AI_API_BASE=https://api.openai.com
AI_API_KEY=your_api_key
AI_MODEL_NAME=gpt-4.1-mini
```

国产模型如果兼容 `/v1/chat/completions`，也可以把 `AI_API_BASE` 指向对应服务地址。

`.env` 会在 Spring 配置绑定前加载，因此 `application.yml` 中的数据库和 AI 占位符会读取 `.env` 对应变量。

## 5. 启动项目

开发启动：

```powershell
.\mvnw.cmd spring-boot:run
```

打包：

```powershell
.\mvnw.cmd clean package
```

运行 Jar：

```powershell
java -jar target/ai-testops-0.0.1-SNAPSHOT.jar
```

## 6. 页面操作流程

打开：

```text
http://localhost:8080/
```

推荐验证路径：

1. 在“文本建档”区域输入标题和需求内容。
2. 点击“创建文本文档”，页面会自动填入返回的 `documentId`。
3. 点击“解析文档”，后端会清洗文本并生成 chunks。
4. 点击“查询详情”查看 document 基础信息和解析状态。
5. 点击“查询 Chunks”查看分块结果。
6. 点击“提取结构化需求”，生成 requirement extract 和 generation record。
7. 点击“生成测试用例草稿”，保存 AI 输出校验结果和草稿用例。
8. 点击“查询校验结果”“查询草稿”，查看生成质量和待评审用例。
9. 可编辑草稿标题，点击“确认草稿”写入正式测试用例，或点击“驳回草稿”记录原因。
10. 点击“查询正式用例”“查询评审记录”核对人工处理结果。
11. 点击“导出 JSON”“导出 Excel”导出正式测试用例。
12. 也可以在“文件上传”区域上传 `md/txt/pdf/doc/docx/xls/xlsx/ppt/pptx` 文件后再解析。

## 9. 常见问题

### 访问 `/` 仍然没有页面

确认项目已重新启动，并确认文件存在：

```text
src/main/resources/static/index.html
```

如果使用 Jar 运行，需要重新执行：

```powershell
.\mvnw.cmd clean package
java -jar target/ai-testops-0.0.1-SNAPSHOT.jar
```

### 数据库连接失败

检查远程 MariaDB 是否可访问、表结构是否已存在、`.env` 中 `DB_URL/DB_USERNAME/DB_PASSWORD` 是否正确。

### 文件上传成功但解析失败

先看接口返回的 `message`，再看后端日志中的 `documentId`。第一阶段解析依赖 Apache Tika，受文件是否损坏、加密、格式异常影响。

### AI 解析为什么返回 MOCK 内容

默认 `AI_PROVIDER=MOCK`，用于本地无密钥联调。要让 AI 真正参与需求解析，配置真实 `AI_PROVIDER/AI_API_BASE/AI_API_KEY/AI_MODEL_NAME` 后重启服务。
