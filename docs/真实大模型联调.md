# 真实大模型联调

第三阶段目标是把 AI 流程从 MOCK 切到真实 OpenAI-compatible 模型，并记录模型名称、Prompt 版本、输入长度、JSON 合法性、用例数量、字段缺失和校验通过情况。

## 1. 配置

在项目根目录 `.env` 增加真实模型配置，不要提交真实密钥：

```properties
AI_PROVIDER=OPENAI
AI_API_BASE=https://api.openai.com
AI_API_KEY=your_api_key
AI_MODEL_CODE=default
AI_MODEL_NAME=gpt-4.1-mini
AI_TEMPERATURE=0.2
AI_MAX_TOKENS=4096

# 仅在供应商明确支持 OpenAI response_format 时开启
AI_JSON_MODE=false
```

国产或私有模型只要兼容 `/v1/chat/completions`，把 `AI_API_BASE` 和 `AI_MODEL_NAME` 换成对应值即可。

## 2. 启动

```powershell
.\mvnw.cmd spring-boot:run
```

启动后先检查模型连通性：

```powershell
Invoke-RestMethod -Method Post -Uri "http://localhost:8080/api/ai-testops/ai/health/check"
```

返回中重点看：

```text
mockMode=false
configured=true
reachable=true
jsonValid=true
latencyMs=<模型请求耗时>
```

## 3. 端到端冒烟

运行脚本：

```powershell
.\scripts\real-llm-smoke.ps1
```

脚本会执行：

```text
健康检查
创建文本需求文档
解析文档
真实模型抽取结构化需求
真实模型生成测试用例草稿
查询校验结果和草稿数量
写入 docs/reports/real-llm-smoke-*.json
```

如果只是验证脚本链路但仍使用 MOCK，可以显式加参数：

```powershell
.\scripts\real-llm-smoke.ps1 -AllowMock
```

## 4. 联调记录指标

每次联调记录至少关注：

```text
provider
modelName
Prompt 模板 code/version
inputTextLength
requirementTokenInput / requirementTokenOutput
testCaseTokenInput / testCaseTokenOutput
draftCount
validationCount
failedValidationCount
```

若 `failedValidationCount > 0`，优先查看 `/api/ai-testops/validations/{generationId}` 和生成记录中的 `errorMessage`，再调整 Prompt。单次只改一个变量，例如 JSON-only 约束、异常场景约束、requirement_refs 约束或 coverage_summary。

Prompt 版本创建、启用和质量对比见 [Prompt版本化与质量闭环.md](Prompt版本化与质量闭环.md)。
