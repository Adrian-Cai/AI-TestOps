## 接口列表

### 1. 上传文档

| 属性 | 值 |
|------|-----|
| **接口名称** | 上传文档 |
| **请求方法** | POST |
| **请求路径** | `` |
| **Content-Type** | `multipart/form-data` |
| **接口标签** | `upload_document` |

**请求参数：**

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| title | string | 是 | 文档标题，格式：`perf-upload-{timestamp}-{iteration}` |
| file | file | 是 | 上传文件（Markdown格式） |

**成功响应：**

```json
{
  "code": 0,
  "data": {
    "documentId": "DOC_20260516_000001"
  }
}
```

**性能阈值：**

| 指标 | 目标值 |
|------|--------|
| 平均响应时间 | < 500ms |
| P95响应时间 | < 1000ms |
| P99响应时间 | < 2000ms |

## 压测场景

### 场景一：上传解析流程 (upload_parse)

**流程步骤：**

1. 上传文档 → 获取 `documentId`
2. 解析文档（使用上一步的 `documentId`）
3. 等待思考时间（1秒）

**数据依赖：**
- 需要准备测试文件：`fixtures/需求文档01_智能订单履约与售后协同系统.md`

---

### 场景二：审批导出流程 (approve_export)

**流程步骤：**

1. 批量审批草稿用例
2. 导出JSON格式（可选）
3. 导出Excel格式（可选）
4. 等待思考时间（1秒）

**数据依赖：**
- 需要准备 `draft-groups.example.json` 文件
- 每个group包含：`documentId`、`draftCaseIds`、`reviewer`

**测试数据示例：**

```json
[
  {
    "documentId": "DOC_20260516_000001",
    "draftCaseIds": [
      "DRAFT_20260516_000001",
      "DRAFT_20260516_000002",
      "DRAFT_20260516_000003",
      "DRAFT_20260516_000004",
      "DRAFT_20260516_000005"
    ],
    "reviewer": "perf_user"
  }
]
```
